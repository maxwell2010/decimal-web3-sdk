# Общий протокол PythonSDK и CandyConsole

Проверено 2026-09-08. Только Decimal Mainnet, chain ID 75.

## Что можно переиспользовать

Канонический профиль: `src/decimal_web3_sdk/profiles/candy_mainnet_v1.json`.
Он содержит версии, адреса системных контрактов и ABI. Входит в wheel через
`profiles/*.json`. Модуль `decimal_web3_sdk.candy_protocol` строит **неподписанный**
вызов без ключей, HTTP-запросов и отправки транзакций.

```python
from decimal_web3_sdk.candy_protocol import build_unsigned_candy_call

draft = build_unsigned_candy_call(
    owner="0x1111111111111111111111111111111111111111",
    address="0x3333333333333333333333333333333333333333",
    contract_type="nft",
    signature="safeTransferFrom(address,address,uint256)",
    args=[
        "0x1111111111111111111111111111111111111111",
        "0x2222222222222222222222222222222222222222",
        2,
    ],
)
# draft: {chainId, from, to, data, value}. Примерные адреса, не отправлять!
```

Это кодировщик, **не разрешение на расходование средств**. Перед использованием
любой проект обязан проверить сеть, адрес подписанта/HD-индекс, владельца NFT или
права создателя, баланс, лимиты эмиссии, точный timestamp hold, необходимость
approval; выполнить `eth_estimateGas`; показать неизменяемое подтверждение
с адресами, ID, суммой/value и комиссией. Указанный `owner` не доказывает владение.

Денежные аргументы ABI передаются целыми значениями в минимальных единицах,
NFT ID и количество — uint256, никогда float. `value` JSON-ответа — строка.
Системный адрес и chain ID нельзя переопределить аргументами вызова.

Консоль синхронизирует **данные**, не запускает Python в браузере:

```powershell
node console/scripts/sync-sdk-profile.mjs C:/Users/Maximus/PycharmProjects/PythonSDK
```

Команда вызывается из DecimalApi; сохраняет проверяемую копию профиля в frontend
и выводит SHA-256. Она не обращается в сеть и не читает `.env` или кошельки.
Сборка сайта не зависит от наличия соседнего PythonSDK: snapshot хранится в Git.
Python- и JS-тесты проверяют одинаковую ABI-кодировку ERC721.

## Обнаруженные расхождения старых API

Существующие `config.py`, `token.py`, `nft.py` содержат пользовательские изменения:
они не были автоматически перезаписаны. Новый профиль и bridge добавлены отдельно.

| Область | Старый путь SDK | Проверенный профиль/поведение |
|---|---|---|
| NFT Center | совпадает с Token Center | `0x443cc8ac24630be9257483a09c34ffa81608eace` |
| NFT delegation | `0x5a6533e337f4b7f815aefb0609200acfbe1ba231` | `0xe45adfcc739a0d10ce9462b58866c9a1a06035e2` |
| Сбор за символ | для 7+ символов зашито 250 DEL | `getCommissionSymbol`: на проверке 0,25 DEL; всегда читать сеть |
| Символ токена | передаётся без нормализации | Mainnet отклонил верхний регистр; передавать нижний |
| Выпуск NFT с DEL | `mintByETH` | проверенный метод `mintByDEL` |
| Новая NFT-коллекция | `createERC721/1155` | подтверждены `createDRC721Reserveless/1155Reserveless`, tuple из 6 полей |
| Изменение токена | `updateDetails` | текущий MINTCANDY поддерживает `updateMaxTotalSupply`/`updateMinTotalSupply` |
| Метаданные NFT | `setTokenURI` предполагается доступным | у Candy этот метод не найден; в UI скрывается |

Источники: официальный dsc-js-sdk (`src/decimalevm/call.ts`), ABI go-smart-node
(`contracts/*`), реестр `contract-center-2`, чтение bytecode/implementation и
симуляция вызовов Mainnet RPC. Одной опубликованной ABI недостаточно: версии
в репозиториях и действующие контракты расходятся. Наличие селектора — лишь
предварительная проверка UI; окончательные ограничения обеспечивает контракт.

## Безопасные границы текущего выпуска

- Есть создание резервных/безрезервных токенов, безрезервных коллекций 721/1155.
- Есть отправка NFT, выпуск, делегирование/hold, отзыв и перенос NFT-позиции,
  сжигание, пополнение DEL-резерва, отключение выпуска — по возможностям контракта.
- Создание **резервных коллекций NFT пока отключено**: сигнатура опубликованного
  SDK не совпадает с действующим NFT Center. Не подбирать ABI при реальной подписи.
- Старые Cosmos NFT с hex-ID без `0x` не считаются ERC20/ERC721-контрактами.
  Их показ сохранён, EVM-кнопки выключены. Нужен отдельный проверенный legacy-путь.
- JSON метаданных задаётся HTTPS/IPFS-ссылкой; загрузка/пиннинг файлов не реализованы.
- Резерв новых NFT в интерфейсе — DEL. Выпуск с резервом ERC20, batch-отправка NFT,
  миграция legacy NFT и массовые операции остаются отдельными этапами.
- ERC721 approval ограничивается одним ID. ERC1155 `setApprovalForAll` явно
  предупреждает о всей коллекции. Следующая транзакция требует отдельного согласия.
- Реальные подписи/отправки при проверках не выполнялись. Нужен контролируемый
  тест пользователем на малой стоимости перед массовым использованием.

Следующий этап объединения — перенести актуальные проверки и расчёт комиссии
в высокоуровневые сервисы PythonSDK, сохранив старые методы через версионированные
адаптеры. Пока нельзя считать старый `client.nft.*` автоматически исправленным
только из-за наличия нового bridge.
