## Разрешения и границы проверки

Совместимый ERC20 permit позволяет включить разрешение в одну транзакцию
мультисенда, обмена либо делегирования. Обычный approve нельзя выдать от имени
кошелька вызовом из multicall: `msg.sender` будет адресом multicall. Поэтому
при отсутствии permit и достаточного allowance SDK по умолчанию возвращает
`extra_steps_required`, ничего не отправляя. Двухшаговый режим включается
только явно через `auto_approve=True` и при отправке требует `wait_receipt=True`.
Для NFT-делегирования в проверенном ABI нет permit - нужно ранее выданное
разрешение оператору или отдельная транзакция approve. DEL не требует approve.

Запросы переноса и анбонда стейка еще не завершены: по событиям они ожидают
окончания заморозки. Финальный вывод после созревания не проверялся.
Стейкинг NFT, управление валидатором, чеки, мост и мультисиг в этой серии
не отправлялись; у них есть офлайн-тесты, но нет новых testnet receipt.
Это предварительный релиз, не подтверждение полного совпадения с JS/Go SDK.
