## Исправление маршрута NFT

Старый testnet DelegationNFT `0x07e2...1a20c` возвращает `deprecated`.
Его сообщение указывает на общий Delegation
`0x0d8e8ce36dade42682dd8cc6288d6a8d324bac2c`. Официальный
testnet API отдает ABI реализации этого прокси. В SDK testnet-маршрут
переведен на общий контракт; ABI записан в пакет из официального
[Contract Service](https://testnet-api.decimalchain.com/api/v1/contracts/compact/0x5d43b2125bf29d5d8174ddc9ee0e54160001c388).
Mainnet-маршрут не изменен. Новый NFT ABI имеет другие имена функций и
структуру `getNFTStake`. Для переноса/отзыва DRC1155 он принимает весь
стейк по ID без аргумента суммы; SDK предварительно сверяет сумму запроса
с текущим стейком и не допускает тихого частичного вывода.

Чтение `getFreezeTime` в testnet вернуло 600 секунд для вывода и 300 секунд
для переноса. `getNFTStake`, `getNFTStakeId`, `getFrozenStake` проверены
на живом контракте. Запрос переноса создал запись очереди №190 с
`unfreezeTimestamp=1790566623`. После `complete([190])` старый валидатор
показал 0, новый 1 NFT, а очередь перешла из статуса 1 в 0. Запрос отзыва
создал очередь №191 с `unfreezeTimestamp=1790567374`. После созревания
`complete([191])` NFT вернулся на кошелек, стейк нового валидатора стал 0,
очередь перешла из статуса 1 в 0. Семейство старых NFT-вызовов `*WithReset` и `resetHolds`
не включено на общем контракте: SDK явно отклоняет их, а не отправляет
устаревшие селекторы.
