# NFT
[Оглавление](README.md) | [Все примеры NFT](transactions/nft.md) | [API](reference/nft.md)

Чтение: owner_of для ERC721, balance_of для ERC721/1155 (для 1155 нужен ID),
is_approved_for_all для полномочий оператора коллекции.
В запросах различаются kind="erc721"/"erc1155", token_id и amount.
Списки token_ids/amounts у ERC1155 batch должны быть непустыми и одинаковой длины.

Реализованы методы создания коллекции, mint, transfer/batch transfer,
разрешений на ID/коллекцию, burn, disable mint, URI, DEL-резерва,
делегирования/hold/отзыва и переноса NFT-стейка между валидаторами.
Минимальные единицы резерва, нативный value_wei и количество NFT различаются.
Разрешение оператору может потребовать отдельной транзакции.
Универсальная поддержка NFT permit не заявлена.

## Резерв ERC-1155

Для проверенной реализации Decimal резерв при выпуске задается общей суммой,
а не суммой на один экземпляр. Для нового ID минимальный резерв на экземпляр
проверяется контрактом как целочисленное деление общей суммы на количество.
Для дополнительного выпуска существующего ID точная сумма равна
`rate(token_id) * amount`, где `rate` - текущий резерв ID, деленный на его
`totalSupply` с округлением вниз. Используйте целые числа минимальных единиц,
не `float`. `value_wei` - общая сумма DEL; `reserve_amount_raw` - общая сумма
резервного ERC-20. Не задавайте одновременно оба вида резерва.

Проверки 2026-10-29: на локальном форке mainnet (блок 34334329) для коллекции
`0x40C3341CBEfE853ed5fdA22c95440DD43427994a`, ID 1, ненулевая ставка
`8333333333333333333333` и выпуск трех NFT дали общую сумму
`24999999999999999999999` минимальных единиц ERC-20. После пополнения баланса
и approve только в форке `eth_call` с точной суммой прошел, а на одну единицу
меньше вернул `InvalidReserve`. Подготовительные переводы и approve не
отправлялись в mainnet. Дополнительно новый ID проверен с DEL в mainnet
`eth_call` и с ERC-20 на форке; сумма ниже минимума дала `InvalidMinReserve`.
Это подтверждает указанные сценарии, но не совместимость всех коллекций или
успешную транзакцию mint в mainnet.

Mainnet NFT-адреса синхронизированы с проверенным профилем, наличие кода проверено.
Старые типизированные ABI и текущие варианты контрактов требуют живой проверки
каждого метода. Резервные mint-варианты, reset и завершение не полностью совпадают
с JS SDK. Адаптер candy_protocol имеет отдельный разрешенный mainnet ABI,
но не заменяет все NFT API. Офлайн-кодирование не доказывает поддержку в сети.
